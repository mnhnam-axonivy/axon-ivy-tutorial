# 呼び出し可能なサブプロセス

`SubProcessCall` · `CallSubStart` · `CallSubEnd` · Axon Ivy 14.0

## どんな要素で、いつ使うか

呼び出し可能なサブプロセスは、*呼び出し可能なサブプロセス* の種類のプロセス（ウォークスルー 2.1）で、ほかのプロセスが関数のように呼び出します。3つの要素がかかわります:

- 呼び出す側のプロセスの **Call Sub**:「Call Sub 要素を使うと、あるプロセス（独立したサブプロセス）を別のプロセスに組み込めます。」「メインプロセスから呼び出されたサブプロセスに飛び、サブプロセスを実行して、その後に戻ってくるようなものです。」
- 呼び出し可能なサブプロセスが始まる **Sub Process Start**:「各 Sub Start 要素は Call Sub 要素から呼び出せます。入力と出力のパラメーターを持ちます。」「プロセスエディターのパレットの Subprocess ドロワーにあり、呼び出し可能なサブプロセスでのみ使えます。」
- 終わって呼び出し元に戻る **Sub Process End**。「一般」タブしかありません。

「メインプロセスのプロセスデータの属性が、呼び出されるサブプロセスのパラメーターにマッピングされます。」サブプロセスは自分のデータで動き、結果を返します。

| したいこと | 使う要素 |
| --- | --- |
| 同じステップを複数のプロセスで使う | 呼び出し可能なサブプロセス |
| 1つのプロセスのステップを、読みやすくするためにボックスにまとめる | Embedded Subprocess（ウォークスルー 3.9） |
| 別の人のために、後で独立して動くプロセスを開始する | Trigger Step（パート6） |

Designer では、コマンド *新しい呼び出し可能なサブプロセス* で作成します。

## 詳細

### Call Sub

**一般**、**プロセス**、**出力** の3つのタブがあります。

| タブ | セクション | 役割 |
| --- | --- | --- |
| プロセス | プロセス開始 | 呼び出す開始。プロセス、コロン、シグネチャの形で、例えば `tutorial/part3/ShippingCost:calculate(Number,String)`。*新しいサブプロセスを作成* で作れます。 |
| プロセス | マッピング | その開始の入力パラメーターごとに1行: `param.<名前>` ← `in` の式。「パラメーターのマッピングには任意の IvyScript の式を使えます。」パラメーターのツールチップにその説明が表示されます。 |
| 出力 | マッピング、コード | 呼び出しの後の呼び出し元のデータ `out` と `result`。「変数 `result` には、呼び出されたサブプロセスが返す出力パラメーターが入っています」。最初の行は `out` ← `in` です。 |

### Sub Process Start

**一般**、**開始**、**結果** の3つのタブがあります。

| タブ | セクション | 役割 |
| --- | --- | --- |
| 開始 | シグネチャ | Call Sub が呼び出すときの名前。表示名はタイプ付きでこれに合わせて変わります: `calculate(Number,String)`。 |
| 開始 | 入力パラメーター | 各パラメーターの名前、タイプ、説明。空でもかまいません。 |
| 開始 | マッピング、コード | `param.<名前>` をサブプロセス自身のデータ `out` へ。`in` はありません。 |
| 結果 | 結果パラメーター | サブプロセスが返すもの: 名前、タイプ、説明。 |
| 結果 | マッピング、コード | `result.<名前>` ← サブプロセスのデータ `in` の式。「このタブのロジックはすべて、終了要素に到達したときに実行されます。」 |

### Sub Process End

**一般** だけです。サブプロセスを終え、Call Sub に戻ります。

### 実行時

1. Call Sub が、呼び出し元のデータからパラメーターをマッピングします。
2. サブプロセスは自分の新しいデータで始まります。呼び出し元のデータはありません。同じ名前の呼び出し元の属性も、サブプロセスでは空です。
3. Sub Process Start が `param` をそのデータにマッピングし、コードを実行します。その後、サブプロセスのステップが実行されます。
4. Sub Process End で、「結果」タブが、ステップが終えたときのサブプロセスのデータから `result` を設定します。
5. 呼び出し元に戻ると、「出力」タブが `result` を呼び出し元のデータにマッピングし、プロセスは Call Sub の後に続きます。
6. Call Sub がマッピングしないパラメーターは 0 か空で届き、「結果」タブが設定しない結果パラメーターは 0 か空で戻ります。どちらも報告されません。
7. `out` ← `in` の行のない「出力」のマッピングは、呼び出し元のデータを新しく始めます。呼び出しが返さなかったものはすべて失われます。
8. サブプロセスの Error End はエラーを呼び出し元にスローします。そこで、Call Sub の Error Boundary Event か呼び出し元の Error Start がキャッチできます（[エラー処理](#/part/3/error-handling)）。

2、4（ステップの後の値）、6、7 はドキュメントに記載がありません。2026-11-16 に Designer のエンジン 14.0.1 で確認したものです。

## よくある質問

**サブプロセスに値を渡し、結果を受け取るには？**
Sub Process Start の「開始」タブで入力パラメーターを、「結果」タブで結果パラメーターを宣言します。Call Sub は「プロセス」タブで `param.<名前>` をマッピングし、「出力」タブで `result.<名前>` を受け取ります。

**サブプロセスは呼び出し元のプロセスデータを読める？**
読めません。自分のデータを持ち、受け取るのはパラメーターが運ぶものだけです。必要なものは渡します。

**結果はいつ設定される？**
Sub Process End に到達したときです。「結果」タブは、ステップが終えたときのサブプロセスのデータを読みます。

**Embedded Subprocess との違いは？**
Embedded Subprocess はそのプロセスの一部で、同じデータで動き、ほかから呼び出せません。呼び出し可能なサブプロセスは自分のデータを持つ独立したプロセスで、どのプロセスからでも呼び出せます。

**サブプロセスが失敗するとどうなる？**
そのエラーは呼び出し元に届きます。Call Sub の Error Boundary Event か、呼び出し元の Error Start でキャッチします（ウォークスルー 3.10）。

## よくある間違い

### 渡されないパラメーター

- *症状:* サブプロセスが 0 か空のテキストで計算する。実行は失敗しない。
- *原因:* Call Sub の「プロセス」タブにそのパラメーターの行がない。Designer は何も報告しない。
- *直し方:* 開始が宣言するパラメーターをすべてマッピングする。[ウォークスルー 3.8](#/walkthrough/3.8)

### 設定されない結果

- *症状:* 呼び出し元がサブプロセスから 0 か空のテキストを受け取る。
- *原因:* Sub Process Start の「結果」タブがその結果パラメーターを設定していない。
- *直し方:* すべての結果パラメーターをサブプロセスのデータからマッピングする。[ウォークスルー 3.8](#/walkthrough/3.8)

### `out` ← `in` のない「出力」

- *症状:* 呼び出しの後、呼び出し元の属性が空になる。設定されているのは呼び出しが返したものだけ。
- *原因:* Call Sub の「出力」タブの `out` の行に式がないので、`out` が新しいデータから始まる。
- *直し方:* Designer が書くとおり、`out` ← `in` を最初の行として残す。[ウォークスルー 3.8](#/walkthrough/3.8)

### サブプロセスに呼び出し元のデータを期待する

- *症状:* サブプロセスで、呼び出し元が入れた属性が空になっている。
- *原因:* サブプロセスには自分のデータクラスと自分のデータがある。
- *直し方:* その値のパラメーターを追加し、Call Sub でマッピングする。[ウォークスルー 3.8](#/walkthrough/3.8)
