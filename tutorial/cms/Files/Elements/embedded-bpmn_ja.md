# Embedded Subprocess と BPMN アクティビティ

`EmbeddedProcess` · `EmbeddedStart` · `EmbeddedEnd` · 8つの BPMN アクティビティ · Axon Ivy 14.0

## どんな要素で、いつ使うか

「Embedded Subprocess は、プロセスの一部をボックスにまとめます。」「これにより、プロセスを階層的に構成できます。」「サブプロセスはトップダウンでもボトムアップでも作れます。プロセスの一部を選択して包むか、パレットから（最初は空の）Embedded Sub 要素を挿入します。」

**BPMN アクティビティ** は、意味を持たせた同じ種類のボックスです:「BPMN アクティビティは Embedded Subprocess と同じように動きますが、目的が違います。」アイコンが、図を読む人にそのステップがどんな種類の作業かを伝え、「技術的な実装の詳細」は中に収まります。

| BPMN アクティビティ | リファレンスの言葉 |
| --- | --- |
| Generic | 「特定しないアクティビティ。」 |
| User | 「ユーザーによる実行を伴うアクティビティを示します。」 |
| Manual | 「IT の手段を使わない実行を伴うアクティビティを示します。」 |
| Script | 「プロセスエンジン自身の中での実行を伴うアクティビティを示します。」 |
| Receive | 「メッセージの受信を伴うアクティビティを示します。」 |
| Rule | 「ビジネスルールを評価するアクティビティを示します。」 |
| Send | 「メッセージの送信を伴うアクティビティを示します。」 |
| Service | 「自動化された機能の呼び出しを伴うアクティビティを示します。」 |

キャンバスでは、ボックスの下に + の付いた小さな四角があります。中にプロセスがあるという印です。

| したいこと | 使う要素 |
| --- | --- |
| まとまったステップを畳んで、プロセスを読みやすく保つ | Embedded Subprocess |
| ステップがどんな種類の作業かを図で示す | BPMN アクティビティ |
| 同じステップを複数のプロセスで使う | 呼び出し可能なサブプロセス（ウォークスルー 3.8） |

## 詳細

Embedded Subprocess とすべての BPMN アクティビティには **一般** タブしかなく、タグもありません。表示名、説明、手段とドキュメントです。ボックスが何をするかは、中のプロセスで決まります。

中には、ボックスに入るコネクターごとに **Embedded Start**（「in 1」「in 2」…）が、出るコネクターごとに **Embedded End**（「out 1」…）があります。これらも「一般」タブだけです。プロセスファイルでは、ボックスは自分の要素を `elements` に持ち、Embedded Start と End は自分が属する外側のコネクターを指定します（`parentConnector`）。

プロセスエディターでは、ボックスを開いて中を表示・編集し、そこからプロセスに戻ります。

### 実行時

1. トークンはボックスに到達し、通ってきたコネクターの Embedded Start から中に入ります。
2. 中の要素は、外と同じプロセスデータで実行されます。何も渡されず、何も返されません。中で設定した値は、ボックスの後にもあります。
3. Embedded End で、トークンはその終了のコネクターからボックスを出ます。
4. 中に何もないボックスはトークンを持ったままです。その後は何も実行されず、リクエストはエラーもログの行もなく終わります。
5. エラー処理では「各プロセス（Embedded Subprocess を含む）は別々のプロセスレベル」です。ボックスの中の Error End はエラーをボックスのレベルにスローし、そこでボックスの Error Boundary Event がキャッチします。

1〜4 はドキュメントに記載がありません。2026-11-16 に Designer のエンジン 14.0.1 で確認したものです。5 のボックスの境界イベントも同様に確認しました。

## よくある質問

**Embedded Subprocess は自分のデータを持つ？**
持ちません。自分が含まれるプロセスのプロセスデータで動きます。自分のデータを持つのは呼び出し可能なサブプロセスだけです。

**Embedded Subprocess の代わりに BPMN アクティビティを使うのはいつ？**
図の上で、そのステップがどんな種類かを伝えたいときです。人の作業（User、Manual）、メッセージ（Send、Receive）、ルール、サービスの呼び出し。実行時の動きは同じです。

**Embedded Subprocess を別のプロセスから呼び出せる？**
呼び出せません。そのプロセスに属しています。複数のプロセスで必要なステップには、呼び出し可能なサブプロセスを使います。

**ボックスの中のエラーはどうなる？**
ボックスは自分のレベルです。中の Error End はボックスのレベルにスローし、ボックスの Error Boundary Event がキャッチできます（ウォークスルー 3.10 は Call Sub で同じことを示します）。

## よくある間違い

### 空のボックス

- *症状:* プロセスがボックスで止まる。その後は何も実行されず、ランタイムログにエラーもない。
- *原因:* ボックスをパレットから置いたか、中を削除したため、Embedded Start と End の間に要素がない。
- *直し方:* 中で起こることを Embedded Start から Embedded End までモデル化するか、ボックスを置かない。[ウォークスルー 3.9](#/walkthrough/3.9)

### 呼び出し可能なサブプロセスにすべきところにボックス

- *症状:* 同じステップが複数のプロセスにあり、ボックスのコピーを1つずつ変えている。
- *原因:* Embedded Subprocess は1つのプロセスに属し、コピーは独立した2つ目のボックスになる。
- *直し方:* ステップを呼び出し可能なサブプロセスに移し、必要な場所で呼び出す。[ウォークスルー 3.8](#/walkthrough/3.8)

Embedded Subprocess には設定するものが少ないので、この2つのほかに間違えることはほとんどありません。
