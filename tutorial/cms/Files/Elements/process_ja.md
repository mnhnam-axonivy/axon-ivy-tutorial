# プロセス

`Process` · `CallableSubProcess` · `WebserviceProcess` · `HtmlDialogProcess` · Axon Ivy 14.0

## どんなもので、いつ使うか

**プロセス**はプロジェクトの1つの `.p.json` ファイルです。要素、要素の間のコネクター、そしてそれらを流れるデータからなります。データは**データクラス**で定義します。Designer では、プロセスそのものにもインスクリプションがあります。キャンバス上で何も選択しないと、インスクリプションビューにプロセスが表示されます。

プロセスには4つの種類があります。種類はプロセスを作るときに選びます。Designer には **新しいビジネスプロセス**、**新しい呼び出し可能なサブプロセス**、**新しい Web サービスプロセス** のコマンドがあり、User Dialog ロジックのプロセスはダイアログと一緒に作られます。

| 種類 | 何のためのものか（リファレンスの言葉） |
| --- | --- |
| ビジネスプロセス | 「ビジネスケースを実装するために使う、通常の種類のプロセス」。ユーザーはワークフローの一覧や開始リストから、その Start を選びます。 |
| 呼び出し可能なサブプロセス | 「Call Sub 要素で、ほかのどのプロセスからも呼び出せるプロセス」。独自のデータクラスを持つので、「パラメーターを両方向にマッピングする必要があります」。このガイドのパート3。 |
| Web サービスプロセス | 「1つ以上のオペレーションを持つ Web サービスを提供します」。「プロセスにユーザーとのやり取りが含まれていると、例外がスローされます」。パート7。 |
| User Dialog ロジック | 「User Dialog の振る舞いの実装」。ビジネスプロセスの User Dialog 要素から開始されます。パート5。 |

Embedded Subprocess はプロセスの種類ではありません。プロセスの要素を1つの箱にまとめるもので、どの種類のプロセスでも使えます（パート3）。

## 詳細

ビジネスプロセスのインスクリプションには **一般**、**プロセスデータ**、**権限** の3つのタブがあります。呼び出し可能なサブプロセスも同じ3つです。Web サービスプロセスにはさらに **Web サービスプロセス** タブがあります。User Dialog ロジックのプロセスには「一般」と「権限」しかありません。そのデータはダイアログ自身のものです。

### 一般

| フィールド | 役割 |
| --- | --- |
| 名前／説明 → 表示名 | プロセスの名前で、ファイルの名前です。ここでは変更できません。 |
| 名前／説明 → 説明 | プロセスが何のためのものかを書きます。 |
| 手段／ドキュメント | プロセスに関係するドキュメントへの参照。 |

プロセスにはタグがありません。タグは要素に付けます。

### プロセスデータ

| フィールド | 役割 |
| --- | --- |
| データクラス | プロセスのデータを定義するデータクラス。「どのプロセスにもデータクラスを関連付ける必要があります。そうでないと、タブにエラーが表示されます」。フィールドの横のボタンで、プロセスから見えるデータクラスを選べます。 |

フィールドの下に、Designer は次の注意を表示します: 「プロセスデータクラスが変更された場合、すでに使用しているフィールドはすべて新しいデータクラスに存在しなければなりません。存在しない場合、既存のマッピングとスクリプトは削除されます。」

2つのプロセスが同じデータクラスを使っても構いません（「2つのプロセスが同じデータクラスを指定するのは正当です」）。ただしリファレンスは、「プロセスと同じプロジェクトで定義されたデータクラスだけを設定する」ことを強く勧めています。

### 権限

| フィールド | 役割 |
| --- | --- |
| すべてのワークフローユーザーがエンジンでプロセスを表示できるようにする | エンドユーザーがエンジンでプロセスを表示できるかどうか。「既定では、すべてのビジネスプロセスで許可され、User Dialog ロジックのプロセスでは許可されません」。 |

### Web サービスプロセス

Web サービスプロセスにだけあります。

| フィールド | 役割 |
| --- | --- |
| 修飾名 | 「完全修飾 Web サービス名は、Web サービスのクラスと WSDL の生成に使われます」。 |
| 認証 | なし／コンテナ、WS Security、HTTP Basic。WS Security と HTTP Basic ではパスワードが平文で送られます。信頼できるネットワークか HTTPS でだけ使います。 |

### データクラス

「データクラスは一般に、ビジネスプロセスや User Dialog のプロセスを流れるデータを保持します」。属性にはそれぞれ名前、タイプ、コメントがあります。タイプによって何を保持できるかが決まります。テキストには `String`、計算に使う値には `Number`、はい／いいえには `Boolean`、構造を持つデータにはほかのデータクラスを使います。

データクラスには4つの種類があり、プロセスが使うのはグローバルなものです。これは「自分のプロジェクトと、それに依存するプロジェクトから使えます」。ほかに User Dialog のデータクラス（パート5）、Web サービスの設定から生成される Web サービスのデータクラス（パート7）、データの保存方法も表すエンティティクラスがあります。

### 実行時

1. プロセスの1回の実行が**ケース**で、ケースごとに独自のプロセスデータを持ちます。
2. 新しいケースでは、すべての属性が最初の値から始まります: 「String は空の String に、Number は 0 に、List は空の List に初期化されます」（IvyScript リファレンス）。String の属性が `null` になることはありません。
3. どの要素もデータを `in` として受け取ります。`out` に入れたものが、次の要素に `in` として届きます。
4. スクリプトのローカル変数は、そのスクリプトの実行中だけ存在します。要素から要素へ渡っていくのはプロセスデータだけです。

## よくある質問

**どの種類のプロセスが必要？**
ユーザーやリンクが開始するものにはビジネスプロセス。複数のプロセスで共有するステップには呼び出し可能なサブプロセス。ほかのシステムに Web サービスを提供するには Web サービスプロセス。User Dialog ロジックのプロセスはダイアログと一緒に作られ、それだけを選ぶことはありません。

**2つのプロセスでデータクラスを共有できる？**
はい、リファレンスはそれを認めています。同じプロジェクトのデータクラスを選び、変更するとそれを使うすべてのプロセスが変わることを忘れないでください。

**「一般」タブでプロセスの名前を変えられないのはなぜ？**
名前はファイルの名前だからです。プロセスの名前を変えるには、そのファイルの名前を変えます。

**要素の説明はどこで見られる？**
マウスを要素の上に置くと、説明がツールチップとして表示されます。[ウォークスルー 2.1](#/walkthrough/2.1)

**プロジェクトをインポートしたときにプロセスを開くには？**
その Start にタグ `DEMO` を付けます。このタグは「プロセスの Request Start をデモ用のプロセスとして示します」。

**属性は String と Number のどちら？**
Number は計算に使う値だけに使います。社員番号、郵便番号、電話番号は String です。Number にすると先頭のゼロがなくなります。[ウォークスルー 2.2](#/walkthrough/2.2)

## よくある間違い

### 名前のない要素

- *症状:* キャンバスには要素のアイコンしか表示されず、開かなければ何をするステップなのかわからない。
- *原因:* 表示名が空のまま。
- *直し方:* 「どの要素にも必ず名前を付ける」（リファレンスのヒント）。「Script」ではなく「注文を確定する」のように、何をするかを書く。[ウォークスルー 2.1](#/walkthrough/2.1)

### プロセスに別のデータクラスを選ぶ

- *症状:* 変更の後、プロセスのマッピングとスクリプトがなくなっている。
- *原因:* プロセスが使っていたフィールドが新しいデータクラスにない。フィールドの下の注意書きのとおり、Designer はそれを使うマッピングとスクリプトを削除する。
- *直し方:* 新しいデータクラスに、プロセスが使うすべての属性があることを確かめる。属性を追加したり名前を変えたりするなら、データクラスそのものを変更する。[ウォークスルー 2.1](#/walkthrough/2.1)

### 金額ではない数字を Number にする

- *症状:* "00731" が 731 として届く。
- *原因:* 数値には先頭のゼロがない。
- *直し方:* そうした属性やパラメーターは String にする。[ウォークスルー 2.2](#/walkthrough/2.2)

### 属性の代わりにローカル変数

- *症状:* スクリプトが計算した値が後の要素に見えない。Designer は何も報告しない。
- *原因:* `Boolean approved = …;` のようなローカル変数は、そのスクリプトの実行中だけ存在する。
- *直し方:* 値を `out` の属性に代入する。属性がなければデータクラスに追加する。[ウォークスルー 2.2](#/walkthrough/2.2)

### ほかのプロジェクトのデータクラス

- *症状:* プロセスが、依存すべきでないプロジェクトに依存している。
- *原因:* データクラスのフィールドの横のボタンは、プロセスから見えるすべてのデータクラスを表示する。必要とするプロジェクトのものも含まれる。
- *直し方:* リファレンスが強く勧めるとおり、同じプロジェクトのデータクラスを使う。

### Web サービスプロセスに人の作業

- *症状:* Web サービスを呼び出すと失敗する。
- *原因:* 「プロセスにユーザーとのやり取りが含まれていると、例外がスローされます」。
- *直し方:* Web サービスプロセスにはダイアログもタスクも入れない。
